5. Professor Viva Defense: Top 10 Questions & Bulletproof Answers

Q1: "Why place Amazon SQS between EC2 and Lambda instead of invoking Lambda synchronously?"

Winning Technical Answer: "Synchronous invocation creates tight architectural coupling. Under a 50x retail burst, concurrent Lambda invocations would exceed regional concurrency limits (1,000) or overwhelm our downstream RDS connection pool, resulting in HTTP 504 gateway timeouts and dropped transactions. Amazon SQS acts as a shock absorber: it ingests thousands of messages per second with microsecond latency, persists them across multiple AZs with KMS encryption, and triggers Lambda concurrently within safe capacity boundaries."

Q2: "Why use Polyglot Persistence? Why not store everything in PostgreSQL or DynamoDB?"

Winning Technical Answer: "Because banking ledger mutations and compliance audit trails have fundamentally conflicting database access patterns. Account balance transfers require strict ACID properties with Serializable Isolation to prevent double-spending race conditions — which Amazon RDS PostgreSQL guarantees. However, compliance audit trails are write-heavy, append-only, and scale infinitely without complex joins. Writing audit records to PostgreSQL would cause severe table lock contention and disk bloat. By streaming audit records to Amazon DynamoDB under the BASE model with automated 365-day TTL expiration, we achieve sub-5ms write latencies with zero maintenance overhead."

Q3: "How does KMS Envelope Encryption work, and why not call KMS for every single database row?"

Winning Technical Answer: "Direct KMS API calls for every record would introduce severe latency (15-30ms per network round-trip) and incur high KMS API request charges ($0.03 per 10,000 requests). In envelope encryption, we call KMS GenerateDataKey once to obtain a plaintext data key and an encrypted data key. We encrypt the cardholder payload locally in RAM using AES-256-GCM with the plaintext key, immediately zero out the plaintext key in memory, and persist only the encrypted payload alongside the encrypted data key (the CiphertextBlob). This guarantees FIPS 140-3 HSM master key protection with local compute encryption speed."

Q4: "What happens if a poison pill message with unparseable data enters the queue?"

Winning Technical Answer: "Without a Dead-Letter Queue, a worker failing to deserialize a malformed payload will return an error, returning the message to the queue after the 60-second visibility timeout, causing an infinite retry loop that wastes compute and blocks valid messages. CloudGuard Bank implements an SQS Redrive Policy with maxReceiveCount = 3. After 3 consecutive execution failures, SQS automatically moves the message into CloudGuard-TransactionDLQ, trips the DLQMessagesVisibleAlarm in CloudWatch, and publishes an SNS notification to SecOps while allowing subsequent transactions to process normally."

Q5: "How does the Auto Scaling Group detect node failure if the EC2 instance hasn't crashed completely?"

Winning Technical Answer: "Basic EC2 status checks only monitor hypervisor hardware reachability. If an Express.js node process hangs or enters an infinite loop, EC2 status checks remain green. To solve this, our Auto Scaling Group uses ELB Health Checks tied directly to our Application Load Balancer Target Group. The ALB polls our custom /health endpoint every 15 seconds. If the application process fails to respond with HTTP 200 within 5 seconds for two consecutive checks, the ALB marks the target unhealthy, stops routing traffic, and signals the ASG to terminate and replace the failed instance."

Q6: "How did you mathematically prove a 71.6% FinOps cost reduction?"

Winning Technical Answer: "Traditional banking infrastructure provisions fixed, peak-provisioned on-demand instances: 2x always-on m5.large EC2 instances ($76.80), an unreserved Multi-AZ db.t3.medium RDS instance ($85.60), and provisioned DynamoDB capacity ($39.00), totaling over $148/month. In CloudGuard Bank, we right-sized our compute to burstable t3.micro instances managed by an Auto Scaling Group ($11.20), combined with a 1-Year Reserved Instance for RDS PostgreSQL ($14.50), and fully serverless pay-per-request billing for Lambda, SQS, and DynamoDB ($9.40), bringing our baseline monthly bill down to $42.00 — a verified 71.6% expenditure reduction while remaining under our $5.00 student budget limit."
